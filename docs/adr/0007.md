# ADR-0007: ReportLab para generar el PDF de la carta porte, como documento interno no timbrado

## Estado
Aceptado

## Contexto
El despachador necesita descargar la carta porte de un viaje en PDF con el
formato tradicional impreso (origen/destino, mercancía, medio de transporte,
figura de transporte, recibí de conformidad). El reto es sobre backend y
monitoreo de flotilla, no sobre integración fiscal real con el SAT — no hay
alcance ni tiempo para emitir un CFDI de Carta Porte timbrado de verdad.

## Decisión
Se usa `reportlab.pdfgen.canvas` (`app/pdf_carta_porte.py`) para dibujar el
layout a mano (coordenadas en mm, cajas, texto) y generar el PDF **en
memoria** (`io.BytesIO`), sin escribir archivos temporales a disco. Tanto en
el docstring del módulo como en el pie de página del PDF se deja explícito
que es un documento interno de respaldo/impresión y **no** el CFDI de Carta
Porte timbrado ante el SAT.

## Alternativas consideradas
- **HTML + WeasyPrint/wkhtmltopdf**: permitiría diseñar el layout en
  HTML/CSS, más rápido de iterar visualmente. Se descartó porque
  `wkhtmltopdf` requiere un binario del sistema (no solo un paquete de pip),
  lo que complica el `Dockerfile` y el entorno de CI para el tiempo
  disponible.
- **Timbrado real vía un PAC (Proveedor Autorizado de Certificación)** para
  emitir el XML/PDF fiscal legalmente válido: sería el documento correcto de
  cara al SAT, pero implica contratar un PAC, manejar certificados de sello
  digital (CSD) y las reglas de validación del SAT — totalmente fuera de
  alcance de un reto de 3 semanas.
- **fpdf2** en vez de ReportLab: API de igual nivel (dibujo manual), se
  prefirió ReportLab por ser más común y con más documentación disponible.

## Consecuencias

**A favor:**
- Sin dependencias del sistema fuera de pip (a diferencia de `wkhtmltopdf`),
  lo que mantiene el `Dockerfile` simple.
- El PDF se genera y regresa en memoria sin tocar el disco del servidor.
- Layout totalmente bajo control programático, sin depender de un motor de
  renderizado de HTML externo.

**En contra / riesgos:**
- Cualquier ajuste visual (mover un campo, cambiar tamaño de fuente) requiere
  tocar coordenadas en mm/píxeles a mano en vez de CSS — más tedioso de
  mantener que una plantilla HTML.
- El documento no tiene validez fiscal. El aviso está en el propio PDF y en
  el código, pero es responsabilidad del producto (UI del panel/empleados)
  dejarlo igual de claro para que nadie lo confunda con el CFDI real.
