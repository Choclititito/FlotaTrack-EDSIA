# ADR-0003: Uso de Mapbox para visualización de ubicación y geocodificación inversa

## Estado
Propuesto

## Contexto
El dashboard (épica E4) necesita mostrar en un mapa la ubicación en vivo de
cada camión de la flotilla, usando las coordenadas (`latitude`/`longitude`)
que ya llegan por telemetría vía `POST /devices/{truck_id}/telemetry` y se
guardan en `TelemetryReading`. Además, se quiere poder mostrar una dirección
legible (no solo lat/lon) para que el despachador entienda de un vistazo
dónde está cada unidad, sin tener que interpretar coordenadas.

Restricciones: proyecto de 3 semanas, equipo de 2 personas, sin presupuesto
para un servicio de pago, y el "piso profesional" del reto exige cero
secretos en el historial de git.

## Decisión
Se usará **Mapbox** para dos cosas separadas:

1. **Mapbox GL JS** en el frontend del dashboard, para renderizar el mapa
   interactivo con un marcador por camión, usando directamente las
   coordenadas que ya devuelve la API. No requiere que el backend llame a
   Mapbox para esto.
2. **Mapbox Geocoding API (reverse geocoding)** desde el **backend**, para
   traducir una coordenada a una dirección legible. La llamada se hace desde
   el backend (no desde el navegador) para no exponer el token con permisos
   de escritura al cliente, y para poder cachear resultados.

El token de acceso de Mapbox se maneja como variable de entorno
(`MAPBOX_ACCESS_TOKEN`), nunca en el repositorio, siguiendo el mismo
principio ya aplicado a las credenciales de Postgres (ver `.env.example`).

## Alternativas consideradas

- **OpenStreetMap + Leaflet**: 100% gratuito y sin límite de requests para
  los tiles del mapa (con los servidores públicos de OSM), pero su
  geocodificación inversa (Nominatim) tiene un límite estricto de 1
  solicitud por segundo y su uso comercial/intensivo requiere alojar un
  servidor propio de Nominatim, lo cual no es viable en 3 semanas. Buena
  alternativa "de respaldo" si el token de Mapbox tuviera algún problema.
- **Google Maps Platform**: cobertura y calidad de geocodificación muy
  buenas, pero requiere tarjeta de crédito desde el inicio y su nivel
  gratuito es más limitado que el de Mapbox para map loads. Se descartó por
  fricción de configuración sin beneficio claro para el alcance del reto.
- **No mostrar dirección legible, solo lat/lon en el mapa**: más simple y
  sin llamadas externas adicionales, pero reduce el valor percibido por el
  despachador (usuario principal del producto) y el reto premia justamente
  la claridad con que se comunica el estado del sistema.

## Consecuencias

**A favor:**
- Nivel gratuito de Mapbox cubre por mucho el volumen esperado en 3 semanas
  de desarrollo y una semana de evaluación (miles de map loads y decenas de
  miles de geocodificaciones gratis al mes).
- No requiere tarjeta de crédito para empezar a desarrollar.
- Mapbox GL JS no depende de que el backend llame a ningún servicio externo
  para dibujar el mapa, reduciendo puntos de falla.

**En contra / riesgos:**
- Se introduce una dependencia externa más: si Mapbox tiene una caída o el
  token se agota/revoca, el mapa y la geocodificación dejan de funcionar. El
  estado de los camiones (lat/lon crudos) seguiría disponible vía API aunque
  el mapa falle — se recomienda que el frontend maneje ese caso con un
  mensaje claro en vez de romperse.
- El equipo asume el costo de mantener un secreto adicional (el token) fuera
  del repositorio y de documentarlo en el README para quien clone el
  proyecto.
- Sin caché, llamadas repetidas de geocodificación para un camión detenido
  desperdiciarían cuota — se debe cachear por coordenada (redondeada) para
  evitar pedir la misma dirección una y otra vez.
